# Developer Dashboard Guide

The Zcash Developer Dashboard is a full-stack Next.js application that provides a visual developer cockpit for testing shielded Zcash applications, monitoring consensus node status, inspecting Unified Addresses, and debugging transactions.

> [!IMPORTANT]
> **Availability**: The dashboard package (`@zcash-app/dashboard`) is bundled with `zcash-dev` and available in every scaffolded project via `pnpm dashboard` (or `npx zcash-dev dashboard`). It runs on port **3050** to remain independent of your application on port **3000**. It can also be run directly from a clone of the monorepo repository using `pnpm --filter @zcash-app/dashboard run dev`.

> [!NOTE]
> **Developer Dashboard (Port 3050) vs. Scaffolded Application (Port 3000)**:
> - **Developer Dashboard (`http://localhost:3050`)**: Diagnostic cockpit for low-level node diagnostics, multi-pool balance verification, live block synchronization tracking, diversifier testing, and visual note decryption.
> - **Scaffolded Application (`http://localhost:3000`)**: Your standalone end-user application created with `npx create-zcash-app`. Use it for developing and running your product's front-end and application-specific API routes.
> - See the [Default Ports Reference](../reference/ports.md) for complete port allocations and override instructions.

## 1. Running the Dashboard

### In a Scaffolded Project

In any project created with `create-zcash-app`:

```bash
pnpm dashboard
# or:
npx zcash-dev dashboard
```

### In the Monorepo Clone

When contributing to or developing from the source repository:

```bash
# 1. Clone the repository
git clone https://github.com/Ultra-Tech-code/create-zcash-app.git
cd create-zcash-app

# 2. Install dependencies & build packages
pnpm install
pnpm build

# 3. Launch the dashboard development server
pnpm --filter @zcash-app/dashboard run dev
# Or use the developer CLI helper:
# pnpm --filter zcash-dev exec zcash-dev dashboard --port 3050
```

Once running, navigate to `http://localhost:3050` in your browser.

## 2. Dashboard Tabs Overview

The dashboard UI organizes developer workflows into seven specialized tabs:

### 1. Overview Tab
- **Component**: [`OverviewTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/OverviewTab.tsx)
- **Account Summary**: Displays current account balances split across pools:
  - **Transparent Pool** (unshielded transparent value)
  - **Sapling Pool** (legacy shielded value)
  - **Orchard Pool** (Halo 2 zero-knowledge shielded value)
  - **Ironwood Pool** (NU7 experimental post-quantum shielded value)
- **Node Synchronization**: Displays real-time sync progress and percentage calculated against chain tip height (`syncedHeight / tipHeight * 100`).

### 2. Health Tab
- **Component**: [`HealthTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/HealthTab.tsx)
- **Node & Indexer Diagnostics**: Monitors connectivity and latency to both consensus node (Zebra) and gRPC indexer (lightwalletd or Zaino).
- **Consensus Upgrade Information**: Displays the active network upgrade name (e.g. `NU5`, `NU6`, `NU7`), consensus branch ID, block height, and connected peer count.

### 3. Addresses Tab
- **Component**: [`AddressesTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/AddressesTab.tsx)
- **Unified Address (UA)**: Displays the full Bech32m Unified Address generated by the active account or viewing key.
- **Receiver Breakdown**: Visualizes the underlying receivers bundled inside the UA (Orchard receiver, Sapling receiver, and transparent P2PKH receiver).
- **Diversifier Generator**: Generates diversified Unified Addresses (`getUnifiedAddress(diversifierIndex)`) for one-time order checkout and unlinkable payment routing.

### 4. Send Tab
- **Component**: [`SendTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/SendTab.tsx)
- **Dry-Run by Default**: Transaction drafts calculate ZIP-317 marginal fee requirements, select spendable notes, and simulate proof generation without broadcasting by default.
- **Shielded Memos**: Allows attaching up to 512 bytes of encrypted UTF-8 memos to Orchard and Ironwood outputs.
- **Broadcast Confirmation**: Requires an explicit confirmation toggle to sign and broadcast the transaction to the network.

### 5. Faucet Tab
- **Component**: [`FaucetTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/FaucetTab.tsx)
- **Regtest Mining Controls**: Allows developers to instantly mine 1, 10, or custom blocks via JSON-RPC `generate` on local regtest nodes.
- **Account Funding**: Directs coinbase rewards and regtest faucet funds to designated Unified Addresses for testing.

### 6. Transactions Tab
- **Component**: [`TransactionsTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/TransactionsTab.tsx)
- **Decrypted History**: Displays incoming and outgoing transactions decrypted using the active session's viewing authority.
- **Metadata**: Shows transaction ID, block height, confirmation count, timestamp, and decrypted memo text.

### 7. Explorer Tab
- **Component**: [`ExplorerTab.tsx`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/components/ExplorerTab.tsx)
- **Local Block & Tx Search**: Accepts 64-character transaction IDs, 64-character block hashes, or decimal block heights.
- **Cryptographic Tree Sizes**: Displays commitment tree sizes for Orchard, Ironwood, and Sapling pools.

## 4. Security Architecture

The dashboard implements defense-in-depth security measures to prevent credential theft, SSRF, and cross-site attacks:

### 1. In-Memory Session Store & httpOnly Cookie
- **Source**: [`packages/dashboard/src/app/session.ts`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/session.ts#L11-L38) and [`packages/dashboard/src/app/api/account/import-key/route.ts`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/api/account/import-key/route.ts#L60-L76).
- When a user imports a Unified Full Viewing Key (UFVK), it is stored exclusively in **server memory** (`sessionStore = new Map()`).
- The client receives an opaque cryptographically random session ID stored in an `httpOnly`, `sameSite: 'strict'` cookie (`zcash_dashboard_session`).
- UFVKs and mnemonics are **never persisted to disk**, never stored in browser `localStorage`, never exposed in query parameters, and never logged in console outputs.

### 2. Endpoint Allowlist & SSRF Protection
- **Source**: [`packages/dashboard/src/app/endpoints.ts`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/endpoints.ts#L62-L105) (`isAllowedEndpoint`, `resolveAllowedEndpoint`).
- Dashboard API routes strictly reject connections to arbitrary remote IP addresses or hostnames.
- Only endpoints declared in `ALLOWED_ENDPOINTS` are permitted.
- Developers testing custom local proxy nodes must explicitly opt in by exporting `ZCASH_ALLOW_CUSTOM_ENDPOINT=1` in the server environment.

### 3. Same-Origin Request Verification
- **Source**: [`packages/dashboard/src/app/security.ts`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/security.ts#L15-L56) (`verifySameOrigin`).
- Every state-changing route (such as `/api/account/import-key` and `/api/mine`) validates the browser's `Sec-Fetch-Site` header (rejecting `cross-site`) and verifies that the `Origin` header matches the server's `Host`.
- Cross-origin requests are rejected with `HTTP 403 Forbidden` (`CROSS_SITE_FORBIDDEN` / `CROSS_ORIGIN_FORBIDDEN`).

### 4. Transparent Explorer Source Attribution
- **Source**: [`packages/dashboard/src/app/api/explorer/backend.ts`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/api/explorer/backend.ts#L9-L35).
- Every query served by `/api/explorer` tags the response with an explicit `source` attribute:
  - `local-lightwalletd`: Responded by local gRPC service on loopback.
  - `local-zebra-rpc`: Responded by local Zebra JSON-RPC on loopback.
  - `third-party-rpc`: Responded by an external secondary RPC service.
  - `third-party-lightwalletd`: Responded by a remote public indexer.
  - `fixture`: Responded by offline static fixture data.
- Users always know whether data originated from their trusted local node or an external third party.

### 5. Opt-In Third-Party Fallbacks
- **Source**: [`packages/dashboard/src/app/api/explorer/backend.ts`](https://github.com/Ultra-Tech-code/create-zcash-app/blob/main/packages/dashboard/src/app/api/explorer/backend.ts#L17-L23) (`thirdPartyFallbackEnabled`).
- Secondary third-party RPC and fallback indexers are **disabled by default**.
- The dashboard never leaks transaction lookups to external third-party providers unless the operator explicitly sets `ZCASH_EXPLORER_THIRD_PARTY_FALLBACK=1`.
